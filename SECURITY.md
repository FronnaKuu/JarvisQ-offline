# Security policy

## Reporting a vulnerability

JarvisQ uses **GitHub's private vulnerability reporting** as the primary
channel for security disclosures.

1. Go to the [Security tab](https://github.com/Helldez/JarvisQ/security)
   of this repository.
2. Click **Report a vulnerability**.
3. Describe the issue, the affected component (mobile / desktop / core
   pipeline / SDK patch), and a minimal reproduction if possible.

We will acknowledge receipt within **3 business days** and aim to provide
a substantive response (triage outcome, fix plan, expected disclosure
window) within **10 business days**.

Please do **not** open a public GitHub issue for security-impacting
findings. The private channel keeps the disclosure off the public record
until a fix can be shipped.

## Scope

In scope:

- Code under `src/`, `electron/`, `scripts/`, `modules/device-perf/`.
- Build configuration (`app.json`, `electron-builder.json`,
  `qvac.config.json`, `patches/*.patch`).
- The release-APK and Windows-installer build pipelines.

Out of scope (report upstream instead):

- Vulnerabilities in `@qvac/sdk`, `@qvac/transcription-*`, `@qvac/llm-*`,
  `@qvac/tts-*`, `@qvac/translation-*` — please report at
  [tetherto/qvac-sdk](https://github.com/tetherto/qvac-sdk).
- Vulnerabilities in third-party model weights (Whisper, Parakeet, Qwen,
  Supertonic, Silero, Bergamot) — report to the model maintainers.
- Vulnerabilities in `expo-*`, `react-native-*`, `electron`, or any other
  dependency: report to the respective project.

## What is not a vulnerability

- The app sending traffic to **HuggingFace** or **GitHub** for model
  download. These hosts are documented in
  `src/core/config/HttpModelSources.ts` and the URLs are pinned to commit
  SHAs.
- The connectivity probe to `https://www.google.com/generate_204` (HEAD
  request, no payload, no analytics).
- The Hyperswarm DHT traffic generated by `@qvac/sdk` while it discovers
  P2P peers for model distribution. This is upstream behavior.

## Disclosure timeline

After a fix lands and a release ships, we will publish a GitHub Security
Advisory describing the issue, the fix, and the affected versions. Credit
to the reporter is included unless they prefer to remain anonymous.
